R: Conditions

2026-11-11 22:49:17

Motivation

  • Conditional statements are good for many purposes in coding:
    • conditional iteration
    • binning data
    • catching errors

Conditionally iterating over data can be a powerful tool, for such things as catching errors, testing a user input, or, perhaps more commonly in data analysis tasks, creating categorical values from numeric interval or ratio data.

if ... else construct

if("Afghanistan" %in% gap_dat$country){
  print("Afghanistan in dataset")
}else{
  print("Afghanistan not in dataset")
}
## [1] "Afghanistan in dataset"

if else statements apply a test to a value, and if it returns TRUE, one thing is done, and if it returns FALSE an alternative thing is done. Although this syntax is useful it is limited in it’s applications.

problem: if needs exactly one TRUE or FALSE

# a whole column is many values, so if() doesn't know which to use
if (gap_dat$lifeExp > 60) "long" else "short"
## Error in `if (gap_dat$lifeExp > 60) ...`:
## ! the condition has length > 1
# NA is neither TRUE nor FALSE
x <- NA
if (x > 5) print("big")
## Error in `if (x > 5) ...`:
## ! missing value where TRUE/FALSE needed

The problem is that if ... else asks a single yes/no question. Given a whole column data it will fail, because it can’t tell which of the answers you meant (note that this ties in neatly to our discussion last week about vectorization). A missing value fails too, because “is NA bigger than 5?” has no answer. This is the line between this slide and the rest of the session: if is for one value (an argument, a setting, a check), and ifelse(), case_when() and cut() are for whole columns, the same vectorized idea from the iteration session. Related: use && and || to combine single values inside if, and & and | to combine whole vectors.

A possible solution: chaining multiple if statements

x <- 7

if (x < 6) {
  print("x is less than 6")
}
if (x == 5) {
  print("x is equal to 5")
}else{
  print("x is greater than not less than 6 and is not equal to 5")
}
## [1] "x is greater than not less than 6 and is not equal to 5"

Although I don’t recommend doing this, you can also chain multiple (an infinite!) if statements together.

Iterating over vectors

# create an empty variable to hold our ordered categorical data
gap_dat$income_level <- ordered(NA, levels = c("low-income",
                                                      "middle-income",
                                                      "high-income"))
# start the for loop to add values to income-level based on GDP values
for (i in seq_along(gap_dat$income_level)) { # for each item along the dataframe
  if (gap_dat$gdpPercap[i] <= 10000) { # if gdpPercap is LT = to 10000
    gap_dat$income_level[i] <- 'low-income' # add 'low-income' to that observation's income level variable
  }else if (gap_dat$gdpPercap[i] <= 75000) { # else, if gdpPercap is LT = 75000
    gap_dat$income_level[i] <- "middle-income" #  add 'middle-income' to that observation's income level variable
  }else { # otherwise
    gap_dat$income_level[i] <- "high-income"  #  add 'high-income' to that observation's income level variable
  }
}
summary(gap_dat$income_level)
##    low-income middle-income   high-income 
##          1312           387             5

A more practical implementation of an if else statement would be creating a new variable with values based off of those in another variable. This process can get a little convoluted as it combines an if else statement with a for loop.

As an example, lets assume that we want to categorize countries based on their GDP as either high, middle, or low income. This can be cumbersome. Luckily R offers some simpler options for iterating over data with an if else construct.

ifelse()

# Assign values
# of 'below-average' if lifeExp is equal to or below 59.47 
# and 'above-average' if above 59.47
gap_dat$lifeExp_cat <- ifelse(gap_dat$lifeExp <= 59.47,
                              "below-average",
                              "above-average")

# assign appropriate data type
gap_dat$lifeExp_cat <- ordered(gap_dat$lifeExp_cat,
                               levels = c("below-average", "above-average"))

summary(gap_dat$lifeExp_cat)
## below-average above-average 
##           809           895

R has a built in function, ifelse() that allows us to provide a condition, and, if that condition returns TRUE to do one thing, and if it returns FALSE to do something else. We’ll split life expectancy into ‘above average’ and below average’ categories.

ifelse() construct

# create a numeric vector
some_numbers <- c(6:-4)

# take the square root of each value, which creates a bit of an issue
sqrt(some_numbers)
##  [1] 2.449490 2.236068 2.000000 1.732051 1.414214 1.000000 0.000000      NaN      NaN      NaN      NaN

ifelse() works well when we have a two condition set to work through. One more example, pulled from its documentation, to help avoid an error / warning being thrown or unwanted values being produced…

Solution: use if_else()

# using if else to test for numbers greater than or equal to 0
# if true, calculate the square root
# if false, produce NA
sqrt(ifelse(some_numbers >= 0, some_numbers, NA))
##  [1] 2.449490 2.236068 2.000000 1.732051 1.414214 1.000000 0.000000       NA       NA       NA       NA

We can use if_else() to sort through data. Here we bin the data by those that are above or below zero to avoid taking the sqrt of a negative number.

Same result, less code: case_when() and cut()

income_cw <- dplyr::case_when(
  gap_dat$gdpPercap <= 10000 ~ "low-income",
  gap_dat$gdpPercap <= 75000 ~ "middle-income",
  .default = "high-income"
)

income_cw <- ordered(income_cw,
                     levels = c("low-income", "middle-income", "high-income"))

# cut() takes in a numeric value (gdpperCap)
# sets the bins (breaks)
# and assigns new levels
income_cut <- cut(gap_dat$gdpPercap,
                  breaks = c(-Inf, 10000, 75000, Inf),
                  labels = c("low-income", "middle-income", "high-income"),
                  ordered_result = TRUE)


identical(income_cw, gap_dat$income_level)  # same as the for loop?
## [1] TRUE
identical(income_cut, gap_dat$income_level)
## [1] TRUE
summary(income_cut)
##    low-income middle-income   high-income 
##          1312           387             5

This is the income loop from earlier rewritten two ways. case_when() reads top to bottom and stops at the first condition that’s TRUE, so the order of the lines matters, just like else if. .default catches everything left over. cut() is base R’s tool for binning numbers into ordered categories in one call: breaks are the cut points, and by default each bin includes its upper edge, which matches <= in the loop. identical() checks that all three approaches agree, which is a good habit whenever you refactor code.

case_when()

gap_dat$pop_size <- dplyr::case_when(
  gap_dat$pop <= 1000000 ~ "small",
  gap_dat$pop <= 100000000 ~ "medium",
  gap_dat$pop > 100000000 ~ "large"
)

gap_dat$pop_size <- ordered(gap_dat$pop_size, levels = c("small", "medium", "large"))

summary(gap_dat$pop_size)
##  small medium  large 
##    180   1447     77

case_when() is a more compact version of using multiple if_else statements that is native to dplyr.

switch(): choosing by name

# switch assigns values based on character string
summarise_col <- function(x, stat = "mean") {
  switch(stat,
         mean   = mean(x),     # if stat = 'mean'
         median = median(x),   # if stat = 'median'
         sd     = sd(x),
         # stop defines an error message if input is not accepted
         # can be captured by a log file
         stop("stat must be mean, median or sd, not ", stat))
}

summarise_col(gap_dat$lifeExp, "median")
## [1] 60.7125
summarise_col(gap_dat$lifeExp, "mod")
## Error in `summarise_col()`:
## ! stat must be mean, median or sd, not mod

When you’re choosing between several options by name, switch() is cleaner than a chain of if (stat == "mean") ... else if (stat == "median") .... R matches the first argument against the names and runs that one. An unnamed last argument is the fallback, used here to give a helpful error. Like if, switch() takes one value, not a vector, so it belongs inside functions, not on columns. You can also leave an option empty, as in Americas = , Europe = "west", to have several names share one result.

Catching problems: stop(), stopifnot() and warning()

safe_log <- function(x) {
  # idicates output is not numeric
  stopifnot(is.numeric(x))                    # stop: can't continue
  if (any(x <= 0, na.rm = TRUE)) {            # warn: can continue
    # return descriptive custom warning
    warning("x has values <= 0; log() returns NaN or -Inf for those") 
  }
  # if x is numeric and > 0 return the log of x
  log(x)
}

safe_log(c(1, 10, 100))
## [1] 0.000000 2.302585 4.605170
safe_log("10")
## Error in `safe_log()`:
## ! is.numeric(x) is not TRUE
safe_log(c(-1, 10))
## [1]      NaN 2.302585

Conditions are how your own functions protect their users, including you. stop() halts with a message when continuing would be meaningless; stopifnot() is a shortcut for checks that should always be true. warning() flags something suspicious but lets the code finish. Checking inputs at the top of a function means errors show up where the mistake is made, with a clear message, not three steps later as a confusing result. To handle an error instead of stopping, look up tryCatch().

Takeaway

  • if / else if / else choose what to do for one value
    • the condition must be a single TRUE or FALSE: no vectors, no NA
    • use && / || inside if, & / | for whole vectors
  • For whole columns, use vectorized conditions:
    • ifelse() / if_else() for two outcomes
    • case_when() for many outcomes; order matters, first TRUE wins
    • cut() to bin numbers into ordered categories
  • switch() chooses between options by name
  • stop(), stopifnot() and warning() catch problems early with clear messages
  • When you rewrite code, check that the old and new versions agree with identical()

The main thing to remember from today is the split between single values and whole vectors. if and switch() make one decision, which is why they live inside functions: checking an argument, picking a method, stopping on bad input. When you want a decision for every row of your data, reach for ifelse(), case_when() or cut() instead of wrapping if in a for loop. They’re shorter, faster, and harder to get wrong.
